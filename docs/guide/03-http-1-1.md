<a name="http-1-1"></a>
<h1>
  <picture>
    <source media="(prefers-color-scheme: dark)" srcset="../../resources/docs/guide/h1-http-1-1-dark.svg">
    <img src="../../resources/docs/guide/h1-http-1-1.svg" alt="HTTP/1.1">
  </picture>
</h1>

Your server can already say hello. Now let's give it something more to do.
Register a route, read the request, and fill the response; doba handles the
HTTP/1.1 parsing and wire format around your handler.

<a name="routes"></a>
<h2>
  <picture>
    <source media="(prefers-color-scheme: dark)" srcset="../../resources/docs/guide/h2-routes-dark.svg">
    <img src="../../resources/docs/guide/h2-routes.svg" alt="Routes">
  </picture>
</h2>

A route pairs an HTTP method with an absolute path. Register routes with
*add_route* before starting the server; the handler receives a read-only
request and a response to fill. The
[static_routes example](../../examples/http/v11/static_routes/README.md)
gives **GET**, **POST**,
**PUT**, and **DELETE** their own handlers on **/resources**. Its
[source](../../examples/http/v11/static_routes/main.cpp) starts like this:

```cpp
http_server.add_route(
    method_names::kGet, "/resources", [](const request&, response& res) {
      res.ok_200();
      res.add_header("Content-Type", "text/plain; charset=utf-8")
          .set_body("resource list");
      return;
    });
```

Paths can do more than match literally. The
[parametrized_routes](../../examples/http/v11/parametrized_routes/README.md)
example uses
**/resources/:id/:detailed**. Its handler receives the parsed ID as a
*std::uint64_t* and the detail flag as a *bool*; a failed conversion means
the route does not match. The
[wildcard_routes example](../../examples/http/v11/wildcard_routes/README.md)
ends a route with **/\***
to match descendants such as **/assets/logo.svg**. Its handler can read the
full path from the request. Register routes before *start*; doba rejects
route additions while the server is running.

<a name="reading-requests"></a>
<h2>
  <picture>
    <source media="(prefers-color-scheme: dark)" srcset="../../resources/docs/guide/h2-reading-requests-dark.svg">
    <img src="../../resources/docs/guide/h2-reading-requests.svg" alt="Reading requests">
  </picture>
</h2>

The
[request_information](../../examples/http/v11/request_information/README.md)
example reads the method,
absolute path, request-target form, host, and connection-close preference.
These accessors return views backed by the request, so use them while the
request is alive.

For values after the question mark, the
[query_parameters example](../../examples/http/v11/query_parameters/README.md)
looks up **q** by name
and iterates every parsed pair. Named lookup returns an optional first match;
indexed access also exposes repeated names. For fields, the
[request_headers example](../../examples/http/v11/request_headers/README.md)
shows case-insensitive name lookup and iteration. Check *exist_header* before
*get_header* when a field may be absent: the latter throws if it cannot find
the name.

<a name="request-bodies"></a>
<h2>
  <picture>
    <source media="(prefers-color-scheme: dark)" srcset="../../resources/docs/guide/h2-request-bodies-dark.svg">
    <img src="../../resources/docs/guide/h2-request-bodies.svg" alt="Request bodies">
  </picture>
</h2>

The body arrives through a reader. Check *has_body_reader* first, then call
*get_body_reader* and read until completion. The
[request_body_text example](../../examples/http/v11/request_body_text/README.md)
echoes a POST body; its
[source](../../examples/http/v11/request_body_text/main.cpp) uses this loop:

```cpp
std::array<std::byte, 1024> buffer{};
std::string text;
for (;;) {
  const auto state = req.get_body_reader()->read(buffer);
  if (state.has_error) {
    res.bad_request_400();
    res.set_body("unable to read request body");
    return;
  }
  text.append(reinterpret_cast<const char*>(buffer.data()), state.produced);
  if (state.complete) break;
}
```

*produced* is the valid byte count, *complete* ends the loop, and *has_error*
reports a read failure. The reader gives you decoded payload bytes whether
the request used **Content-Length** or chunked transfer coding. Need raw
bytes rather than text? The
[request_body_binary](../../examples/http/v11/request_body_binary/README.md)
example reads the same way
without treating zero bytes as a terminator.

<a name="building-responses"></a>
<h2>
  <picture>
    <source media="(prefers-color-scheme: dark)" srcset="../../resources/docs/guide/h2-building-responses-dark.svg">
    <img src="../../resources/docs/guide/h2-building-responses.svg" alt="Building responses">
  </picture>
</h2>

Start with a status, then add fields and a body when that status permits one.
The
[response_statuses example](../../examples/http/v11/response_statuses/README.md)
uses helpers for
**201 Created**, **307 Temporary Redirect**, and **204 No Content**. Its
[source](../../examples/http/v11/response_statuses/main.cpp) sets a location
for the created resource:

```cpp
res.created_201();
res.add_header("Location", "/resources/1");
```

Use *add_header*, *set_header*, and *remove_header* to manage fields; the
[response_headers example](../../examples/http/v11/response_headers/README.md)
shows all three. *set_body* accepts text, binary data with an explicit size,
or an arithmetic value in the
[response_body_values](../../examples/http/v11/response_body_values/README.md)
example. For bodies built in parts, the
[response_body_writers](../../examples/http/v11/response_body_writers/README.md)
example uses raw and chunked writers. Its
[source](../../examples/http/v11/response_body_writers/main.cpp) shows both.
Finish a chunked writer with *end* before moving it into the response; doba
then emits the matching framing headers.

Some responses have special body rules. **204 No Content** has no body. The
[head_requests example](../../examples/http/v11/head_requests/README.md)
registers one representation handler for **GET** and **HEAD**; doba keeps
the representation headers for **HEAD** but suppresses its message body.

<a name="async-routes"></a>
<h2>
  <picture>
    <source media="(prefers-color-scheme: dark)" srcset="../../resources/docs/guide/h2-async-routes-dark.svg">
    <img src="../../resources/docs/guide/h2-async-routes.svg" alt="Async routes">
  </picture>
</h2>

A handler can return a task when it needs to pause without blocking its
transport worker. The
[async_routes example](../../examples/http/v11/async_routes/README.md)
puts a coroutine route next to a synchronous one. Its
[source](../../examples/http/v11/async_routes/main.cpp) yields and resumes
before building the slow response:

```cpp
http_server.add_route("GET", "/slow",
                      [](const request&, response& res) -> task<void> {
                        co_await yield();
                        co_await sleep_for(std::chrono::milliseconds(50));
                        res.ok_200().set_body("slow");
                      });
```

If **/fast** finishes first on the same connection, doba still sends the
responses in request order. When stopping the server, pending coroutines
finish before the transport workers stop.

That is the everyday HTTP path. Head back to the [guide index](README.md)
when you're ready for transports and TLS.
